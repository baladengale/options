# Simplified Do-Not-Wheel → Daily Eligibility Check

**Core idea:** the watchlist is the master list. Replace the local blacklist file + auto-add/auto-remove machinery with a simple, daily, **read-only eligibility check** that skips unprofitable companies. You curate the watchlist directly when something is "consistently bad" — no more local `do_not_wheel.yaml` to manage.

## What gets simpler
- **Delete the auto-add/auto-remove logic** in `_print_thesis` (the `dnl.add(...)` / `dnl.remove(...)` block). The thesis validation still *runs* and *displays* — it just no longer mutates a blacklist file.
- **Keep `do_not_wheel.yaml` as an optional manual override** (you can still hand-edit it to force-skip a ticker temporarily), but the engine no longer writes to it automatically. The screener still respects it.
- The `config/do_not_wheel.yaml` changes you've seen (AMD/PLTR/TSLA auto-added) stop happening — those are handled by the eligibility check instead.

## 1. New: `is_wheel_eligible()` — one simple daily check (`src/data/do_not_wheel_list.py`)
A pure function using **moomoo snapshot data only** (no yfinance, fast, runs every day):

```python
def is_wheel_eligible(snapshot) -> tuple[bool, str]:
    """Can we run the Wheel on this stock today?

    Read-only. Blocks only clear, objective failure:
      - Unprofitable: net_profit < 0 AND eps_ttm < 0 (loss-maker)
      - Negative P/E that signals the same (pe_ratio < 0)
    Returns (eligible, reason). Eligible=True means proceed to score/screen.
    """
```
Thresholds from `config/rules.yaml thesis_validation` (already there: `pe_negative_critical`). Moomoo-first by construction — `net_profit` and `eps_ttm` come straight off the snapshot the screener already fetches.

## 2. Screener: skip ineligible tickers (`scripts/screener.py`)
Replace the `DoNotWheelList().is_excluded()` pre-filter (lines 146-149) with `is_wheel_eligible(snap)`. Same skip behavior, but:
- No file I/O, no blacklist to manage.
- Uses the snapshot already fetched for scoring — zero extra API calls.
- Still honors a hand-edited `do_not_wheel.yaml` as a manual override (checked second).
- Logs *why* a ticker was skipped (e.g. "BE: skip — unprofitable (net loss, EPS -5.4)").

## 3. Portfolio `--thesis`: stop mutating the blacklist (`scripts/portfolio.py`)
- Remove the `dnl.add()` / `dnl.remove()` auto-mutation in `_print_thesis`.
- The thesis output now shows each ticker's status (INTACT/DAMAGED/BROKEN) **plus an `[eligible]` / `[not eligible: reason]` tag** from `is_wheel_eligible`, so you see at a glance which names are wheelable today. You decide what to remove from the watchlist.
- Keep `_print_do_not_wheel()` to display the manual-override file (now purely informational).

## 4. Config — one clear block
```yaml
thesis_validation:
  pe_negative_critical: true     # block if P/E < 0 (unprofitable)
  unprofitable_block: true       # block if net_profit < 0 AND eps_ttm < 0
```
Both already mostly present. `unprofitable_block` is the new toggle. Keep `trusted_tickers` for force-allow (rare).

## 5. Daily cadence — already in place
The scheduler runs a **daily 09:00 UTC review**. The screener runs on-demand / via cron. So eligibility is checked every day with no scheduler change — exactly "check these everyday."

## 6. Tests — `tests/test_eligibility.py` (new)
- Unprofitable (net_profit<0 AND eps<0) → not eligible.
- Profitable but negative-EPS-one-quarter (net_profit>0, eps<0) → eligible (not a clear loss-maker).
- Negative P/E → not eligible.
- Healthy company → eligible.
- `unprofitable_block: false` disables the filter (trusted override).
- Screener skip behavior: ineligible ticker excluded from candidates.

## 7. Docs
Update README "Do-Not-Wheel List" section → rename to "Wheel Eligibility" explaining: watchlist is master, daily moomoo-based profitability check skips loss-makers automatically, manual override via `do_not_wheel.yaml` still supported.

## Why this is solid
- **One source of truth**: the watchlist. No local blacklist drift, no 6-month timers, no auto-mutation.
- **Objective & fast**: moomoo `net_profit` + `eps_ttm` — no subjective P/E thresholds blocking growth names, no yfinance dependency for the core check.
- **Read-only**: nothing writes to disk automatically; you stay in control of the list.
- **Backward compatible**: existing `do_not_wheel.yaml` and `DoNotWheelList` class stay for manual overrides; the thesis/loss logic is untouched.
