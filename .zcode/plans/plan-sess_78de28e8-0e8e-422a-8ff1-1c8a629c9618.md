# Implementation Plan: TO-DO fixes + unified engine

Resolving all TO-DO items with config-driven, consistently-implemented backend logic. Each change keeps `src/` as the single source of truth, eliminates duplicated code paths, and is covered by tests. Existing test contracts are preserved.

## 1. Fix P&L discrepancy — unify option-income classification (root cause)

**Bug:** `compute_income()` (src/portfolio/summary.py:61-74) only counts `SELL_SHORT`→collected and `BUY_BACK`→paid. But moomoo returns covered-call sells as plain `SELL`, so CC premium falls into the `elif side == 'SELL'` branch and gets misclassified as `stock_sold` (×100). This is why `--pnl` shows $6,921 while `--orders` shows $7,834, and why `Stock Sold: $76,833` is inflated.

**Fix (src/portfolio/summary.py):**
- Classification must key on **`is_option_code(code)` first**, then side:
  - Option code + (`SELL` or `SELL_SHORT`) → `premium_collected`
  - Option code + (`BUY` or `BUY_BACK`) → `premium_paid`
  - Non-option code + `BUY` → `stock_bought`, `SELL` → `stock_sold` (gross = qty×price, no ×100)
- Monthly bucketing stays option-only.
- **Preserve** all existing tests: `test_income_stock_buys_and_sells` (SELL/BUY on `US.V` stock) still routes to stock buckets because `US.V` is not an option code. `test_income_option_premium_collected_and_paid` (SELL_SHORT/BUY_BACK on option codes) unchanged.

## 2. Unify the `--orders` view onto the shared loader (eliminate duplicate path)

**Problem:** `_print_orders()` (scripts/portfolio.py:281-416) opens its own `OpenSecTradeContext`, fetches a separate 90-day window with no dedup, re-implements `parse_option_code` inline, and tallies income with divergent side-mapping.

**Fix (scripts/portfolio.py):**
- `_print_orders` keeps its display logic but **reuses the already-fetched `orders`** (passed in from `main`, which already called `fetch_portfolio_and_orders`) instead of re-fetching.
- Add a thin `order_income_breakdown(orders, ticker_filter)` helper in src/portfolio/summary.py that filters by ticker and returns rows + totals using the **same** `compute_income` classification. `_print_orders` calls it so the `--orders` totals always agree with `--pnl`.
- Remove the inline `parse_option_code` (use `parse_option_code` from portfolio_loader) and the private `OpenSecTradeContext`.
- Add a date-range filter (default 90 days for display) layered over the shared all-time orders list.

## 3. Make P/E thesis thresholds configurable + add a trust list

**Problem:** `_check_fundamental_health` (src/analysis/thesis_validator.py:240,249) hardcodes P/E >100 = CRITICAL, >50 = WARNING. No config key exists. No per-ticker override. This auto-blocks AMD/PLTR/TSLA.

**Fix:**
- **config/rules.yaml** `thesis_validation` section — add:
  ```yaml
  pe_ratio_warning: 50        # DAMAGED if above
  pe_ratio_critical: 100      # BROKEN if above
  pe_negative_critical: true  # BROKEN if P/E < 0
  trusted_tickers: []         # skip the P/E check entirely (e.g. [AMD, TSLA])
  ```
- **src/config.py** — add a `thesis_validation(key, default)` accessor mirroring the existing `holdings_exit`/`thesis_gate` pattern, plus `trusted_tickers` property.
- **src/analysis/thesis_validator.py** — `_check_fundamental_health` reads thresholds from config; if `ticker in trusted_tickers`, return None (skip P/E). Apply the same config + trust logic to `quick_thesis_check` (lines 451-459) for consistency.

## 4. Extend thesis validation to options positions

**Problem:** `_print_thesis` (scripts/portfolio.py:734) loops `pf.stocks` only — options underlyings are never thesis-checked.

**Fix (scripts/portfolio.py `_print_thesis`):**
- Build the validation set as `set(pf.stocks) | pf.option_tickers` (underlyings of open option positions). Also include watchlist tickers if desired — but per the TO-DO ("watchlist + options + stocks together"), include all three.
- Distinguish the source in output (e.g. label `[stock]`/`[option]`/`[watch]`) so the user knows where each ticker comes from.
- Do-Not-Wheel auto-add applies to any BROKEN ticker across the unified set.
- Avoid duplicate work: validate each ticker once even if it appears in multiple sets.

## 5. Auto-remove Do-Not-Wheel on thesis recovery

**Problem:** `dnl.remove()` is only ever called on 6-month expiration. A recovering stock stays blocked.

**Fix (scripts/portfolio.py `_print_thesis`):**
- After validating, for every ticker currently on the Do-Not-Wheel list whose **latest** status is INTACT (or DAMAGED, configurable), call `dnl.remove(ticker)` and print a "✅ Removed X — thesis recovered" line.
- Conservative default: only auto-remove on INTACT (not DAMAGED) to avoid whipsaw. Keep the 6-month expiration as a hard floor safety net for tickers never re-validated.
- Add `recovery_status_for_removal: INTACT` to config under thesis_validation for tunability.

## 6. Document BP semantics + caching reality (README)

The TO-DO asks "is the caching engine required?" and "are these funds latest?" — the investigation proved there is **no caching engine** (only trivial per-session dicts) and funds are always fetched fresh (`refresh_cache=True`). The BP swing ($21k vs $78k) is the `_buying_power()` field-selection (margin `power` vs cash `usd_net_cash_power`), not staleness.

**README updates:**
- Add a "Data Freshness & Caching" subsection stating: no caching engine; funds/positions/orders always fetched live with `refresh_cache=True`; only per-session OHLCV/chain dicts exist (cleared at process exit).
- Clarify the buying-power field selection and that BP can legitimately vary between margin-inclusive and cash-only depending on which field moomoo returns.
- Document the new P/E config + trust list, thesis-on-options, and Do-Not-Wheel auto-recovery.
